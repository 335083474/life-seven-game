# 命运之书：单人游戏接入

2026-10-26。`book/` 从独立的三段示例改为原单人游戏的 Three.js 呈现端。采用现有 `solo-1.1-preview`，没有重新定义固定事件、奖励、黑天鹅概率或生存规则。原页面仍可游玩，两种界面共享同一浏览器身份、当前人生、草稿和请求回执。

## 运行边界

- `game.js` 继续负责全部交互、语言、草稿、API 调用、重试和存档恢复；新增可选 `LifeBook` 呈现钩子，原二维入口不需要该钩子。
- `prototype/src/life-book.ts` 将同一套真实控件排进书页，保留取舍、保护、婚姻、生育、抚养、夫妻交换、NPC 合作、机遇、手记搜索、来源核验、典藏和终局入口。书页可滚动，右上方可靠近阅读；手机也能打开完整档案。
- 桌上卡牌读取真实持有元素、等级和投入状态。自由事件点选卡牌；其他阶段点选查看卡牌说明。配偶资源仍在书中选择，至多两张约束沿用原逻辑。
- 自由行动、黑天鹅及明确选择的机遇重掷，先收到服务端保存的骰点，再播放 Rapier 轨迹。不会在本机再抽一个结果。动画失败不丢弃存档、不重复投骰，显示已保存结果；刷新从服务端继续。
- MiniMax 批量评估、换卡本地重算、短手记流式显示、终局分七章生成长传记沿用原实现。未加入浏览器密钥、另一套结算或演示 AI。
- 阅读字号、纸页控件、三维卡面使用古书风格；正文字体扩充至游戏文字及 GB2312 字符，少见字由系统字体回退。场景说明和外观面板随游戏语言切换。

## 验证

- 根目录规则/API/语言/流式测试：64 项通过。
- 三维项目：16 项通过，包含原有模型/翻页/48 组物理轨迹，以及新增共享真实 UI 的九回合、七章传记全流程测试。该全流程使用测试数据库和模型响应，不冒充真实 MiniMax 验证。
- 新增测试还覆盖换卡不重复调用模型、呈现中断不丢失已提交结果、刷新所用存档标识、100 与重掷的骰点映射。
- 真实公开 API 浏览器验收：新局、刷新续玩、升学固定事件、桌上选卡、MiniMax 评估、点击三维骰子、普通失败结算、MiniMax 短手记。该次自由行动成功率 38%，服务端结果 81，三维与书页同为 81，普通失败没有扣牌。
- 浏览器另行检查桌面/390×844 手机视口、滚动阅读、完整档案及语言切换。发布后核对实际构建文件和页面交互。

## 本地运行

`npm run dev --prefix prototype` 使用 `http://127.0.0.1:8767/`，与现有 API 的开发来源白名单一致。`npm run build --prefix prototype` 生成 GitHub Pages 的 `book/`。原网站也可在仓库根目录用 8767 端口提供静态服务。

此轮范围是已有单人内容进入三维版。规则待定项仍见 `rules-contract.json` 和 `docs/development-audit.md`；真人联机、广告、收款与付费 PDF 不在此次接入范围。暗色符文骰仍只有百分骰模型，保持预览状态，不替代完整的古铜套骰。
